# Prism working rules

Read [docs/README.md](docs/README.md) and the relevant source document before changing anything.

- Repository documentation is the source for specifications, decisions and evidence. Shortcut owns delivery status. Chats are working conversations.
- Write repository content in plain English. Lead with the reader's task or conclusion.
- Separate proposals, accepted decisions, observations and unverified assumptions. Never invent evidence or approval.
- Keep one source for each fact; link rather than duplicate. Update affected references with each change.
- Use synthetic data and virtual money only. Never include credentials or personal data.
- Inspect the working tree first. Preserve unrelated changes. Never use destructive resets or force pushes.
- Work on a branch and propose changes through a PR. Do not merge, publish or change access without authorization for that action.
- Report checks actually run and their limits. A skipped or unavailable check is not a pass.
- Read only relevant context. Finish each work session with a short handoff update when work remains.
- Create reusable skills only for repeated, proven procedures. Skills link to standards rather than copying them.
